# Grokbot: база референсов для MYOR

Исследовано 6 октября 2026. **Публикация:** описанный ниже локальный архив не включён в этот репозиторий. Галерея использует исходные URL; видео, изображения, кадры и сторонние снимки кода здесь не хранятся. Для локального повторения экспорта см. README. Цель — свой персонаж с динамичной формой в габарите 1:1, который реагирует на события онбординга и чата в Expo / React Native и вебе. Дизайн ещё не утверждён; внешний вид задаётся конфигурацией бэкенда.

## Что удалось получить

Из [публичного кейса Novra](https://www.novra.design/case-studies/grokbot) сохранены **77 оригинальных файлов**: 29 WebM, 29 постеров, 18 изображений и один интерактивный `.riv`. К ним созданы 29 PNG-листов и 232 отдельных кадра. Реестр `assets.json` содержит исходный URL, размер и SHA-256 каждого файла. В `index.html` — просмотр, воспроизведение, скачивание и таймкоды. Кадры взяты равномерно по времени: это обзор движения, а не авторская раскадровка или полный набор ключевых поз. Несколько очень коротких клипов дают повторяющиеся кадры.

Отдельный обзорный ролик доступен в [исходном embed](https://player.mediadelivery.net/embed/758467/92b79cf7-4662-4754-bdf2-7caf81bc7ea7); он не включён в число 29 скачанных роликов. Его поток вернул 403, поэтому сохранена ссылка.

Кейс обозначен **Independent Concept**. Его сцены с notch, виджетами и Live Activity — дизайн-концепт; они не доказывают наличие готовой продуктовой интеграции с iOS. Публичного редактируемого проекта Novra `.rev`, Figma-файла или репозитория приложения в исследованных источниках не нашёл.

## Какие референсы брать первыми

| Материал в галерее | Что извлечь для MYOR |
|---|---|
| 20 Follow | Направление взгляда; на телефоне заменить мышь ограниченным взглядом на активный элемент / касание |
| 22 Annoyed, 24 Slap, 26 Dizzy | Деформация, задержка реакции, восстановление формы. Образцы динамики, не обязательные продуктовые эмоции |
| 28 Upload | Связь движения с действием пользователя и завершением загрузки |
| 30 Error, 32 Finished, 34 Working | Различимые статусы, вход, цикл, выход и возврат в спокойное состояние |
| 36 Figma logic, 37 Rive state machine | Устройство переходов и связи между действиями и анимациями |
| 54–60 Sketches / Vector / explorations | Поиск силуэта, расстояний между глазами, материала и читаемости характера |
| 12–18, 38–43 | Роль персонажа в интерфейсе и компактных контейнерах |

Полезный принцип Novra: персонаж показывает состояние задачи и реагирует на пользователя через короткие переходы. Перенести этот принцип на собственный силуэт 1:1 проще, чем пытаться перекомпоновать весь notch-артборд.

## Что находится в настоящем Rive-файле

Файл `assets/rive/77-Novra-Grokbot-interactive-runtime.riv` — около **1,07 MiB**. Внутри два артборда: `Main ` и `Main 2`, несколько state machines, 75 имён таймлайнов суммарно. Эти имена включают тестовые и вспомогательные анимации, поэтому это **не 75 готовых эмоций**.

Плеер использует `Main 2` / `State Machine_Main`, `autoBind` и View Model. Найдены 13 свойств: `reset`, `followX`, `followY`, `targetX`, `targetY`, `In and Out of artboard`, `Working hover`, `left`, `right`, `taskfinished`, `error`, `uploadfile`, `work`. Обычный список legacy inputs пуст; управление идёт через data binding.

**Проверено в браузере:** файл загружается, рендерится и отвечает на переходы working → error → working → finished → working → upload. Логи в `rive-qa.json`, структура в `rive-inspection.json`, локальный плеер в `rive-player.html`. Это проверка веб-экспорта; теста на iOS / Android и замеров FPS пока нет. В файле вся notch-композиция, а не отдельно подготовленный аватар. Демо-плеер открывает свойства напрямую и не воспроизводит все ограничения кнопок исходного сайта.

`.riv` — runtime-экспорт. Чтобы удобно менять геометрию, привязки и анимации в редакторе, нужен `.rev` либо доступ к авторскому Rive-проекту. [Rive удалил импорт `.riv` в редактор](https://rive.app/changelog) в декабре 2023. Не стоит строить план редизайна на обратной конвертации этого файла. Надёжный путь — собственный риг с аналогичным поведением; при доступе к `.rev` автора можно отдельно оценить перенос контроллеров.

| [Louis-CFM/coucou](https://github.com/Louis-CFM/coucou) | Уже исследованная процедурная база: Canvas, физика, реакты и экспорт кадров | MIT для кода; отдельная LICENSE-ASSETS резервирует персонажа Mochi и его ассеты |

Сохранены локальные **снимки для изучения** в `sources/svg-study` и `sources/flutter-study`, включая геометрию / каталог / runtime и upstream notices. Коммиты закреплены в `PROVENANCE.json`. Они не подключены к приложению MYOR. Для SVG-study сохранён компонент без исторических release ZIP; для Flutter — `lib`, README и лицензия. Их заявленные upstream тесты не запускались.

Наиболее близок к динамичной форме 1:1 именно SVG-study. Из него полезно изучить разделение формы, выражения и состояния, равномерную геометрию морфинга и управление временем. В продакшен переносить собственные формы и разрешённые алгоритмы после проверки условий использования, а не весь Grok-каталог.

## Интеграция в MYOR

| Вариант | Web | Expo / React Native | Пересборка под свой дизайн |
|---|---|---|---|
| Собственный Rive | Официальный React runtime | Новый `@rive-app/react-native`, Nitro Modules, development build | Редактор, риг, state machine, View Model; нужны собственные `.rev` + `.riv` |
| Собственная процедурная графика | Canvas / SVG | Skia + Reanimated, уже есть в MYOR | Полный контроль динамичной формы; придётся написать адаптеры, морфинг и движение |
| Собственный sprite atlas | Canvas или смена кадров | Skia / контролируемый atlas renderer | Простая доставка готового движения; каждую форму / палитру обычно нужно заново экспортировать |

В `ui-lab/native/package.json` сейчас Expo 57, React Native 0.86, Skia 2.6.2 и Reanimated 4.5.1. Rive не установлен. По текущей [документации Rive RN](https://rive.app/docs/runtimes/react-native/react-native) база проекта выше минимальных Expo / RN версий; это ещё не подтверждает сборку со всеми текущими native-зависимостями. [Expo-интеграция](https://rive.app/docs/runtimes/react-native/adding-rive-to-expo) требует development build; Expo Go для этого runtime не подходит. Для веба см. [официальный React runtime](https://rive.app/docs/runtimes/react/react).

**Рекомендация:** начать с собственного простого шейпа и одинаковых 2–3 движений в лаборатории Rive и Skia; проверить их на целевых устройствах и выбрать основной рендерер. Rive выглядит удобнее для работы дизайнера над авторским ригом и переходами. Skia подходит, если изменение формы — основа характера и его удобнее задавать процедурно. Sprite atlas оставить как вариант фиксированных клипов; не делать его источником истины для неопределённого дизайна.

Виджеты и Live Activity вынести в следующий этап. [Apple описывает их анимации через SwiftUI и обновления данных](https://developer.apple.com/documentation/widgetkit/animating-data-updates-in-widgets-and-live-activities); работающий Rive в обычном RN-экране не переносит произвольную интерактивную сцену в эти системные поверхности автоматически.

## Условия использования набора

Novra / Grok / авторские материалы сохранены как визуальные референсы с указанием источников. Лицензия на использование их персонажа, анимаций, видео и `.riv` в MYOR не обнаружена. Находящийся рядом MIT-лицензированный Rive runtime — отдельное программное обеспечение и не лицензирует сам дизайн. Перед поставкой должны использоваться собственные ассеты либо материалы с отдельно полученными правами.

Для решения текущей задачи достаточно разработать свой образ по этим референсам. Конкретный объём, события, артефакты и приёмка зафиксированы в `TASK.md`.
